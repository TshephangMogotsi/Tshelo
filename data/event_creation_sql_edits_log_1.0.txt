TSHELO EVENT CREATION SQL EDITS LOG 1.0
=======================================

Purpose
-------
This file records the database and Row Level Security changes made while wiring
the Create Event screen to insert real events into Supabase.


1. Event Type Flexibility
-------------------------

Problem:
- The app supports standard event types and a custom "Other" event type.
- The original events.event_type column used a PostgreSQL enum.
- Custom event names would fail if the value was not already in the enum.

Change:

ALTER TABLE public.events
ALTER COLUMN event_type TYPE character varying
USING event_type::text;

Result:
- Standard and custom event types can now be stored.
- The app can still validate standard types against public.event_type_config.


2. Event Emoji Storage
----------------------

Problem:
- The Create Event screen lets users choose an emoji.
- The events table had no column for that selection.

Change:

ALTER TABLE public.events
ADD COLUMN IF NOT EXISTS event_emoji character varying;

Result:
- The selected emoji can be saved and shown later on event cards/detail screens.


3. Event Code And Share Code Defaults
-------------------------------------

Problem:
- events.event_code was required, but the app did not generate it.
- events.share_code is needed for RSVP/share links.
- First attempt failed because generate_share_code() did not exist.
- Second attempt failed because generate_event_code() already existed with a
  different return type.

Final shape:
- Use database functions for both codes.
- Use character varying return types to match the events columns.
- Set the functions as column defaults.

SQL:

CREATE EXTENSION IF NOT EXISTS pgcrypto;

CREATE OR REPLACE FUNCTION public.generate_event_code()
RETURNS character varying
LANGUAGE plpgsql
AS $$
DECLARE
  candidate character varying;
BEGIN
  LOOP
    candidate := 'EVT-' || upper(substr(replace(gen_random_uuid()::text, '-', ''), 1, 8));

    EXIT WHEN NOT EXISTS (
      SELECT 1
      FROM public.events
      WHERE event_code = candidate
    );
  END LOOP;

  RETURN candidate;
END;
$$;

CREATE OR REPLACE FUNCTION public.generate_share_code()
RETURNS character varying
LANGUAGE plpgsql
AS $$
DECLARE
  candidate character varying;
BEGIN
  LOOP
    candidate := upper(substr(replace(gen_random_uuid()::text, '-', ''), 1, 10));

    EXIT WHEN NOT EXISTS (
      SELECT 1
      FROM public.events
      WHERE share_code = candidate
    );
  END LOOP;

  RETURN candidate;
END;
$$;

ALTER TABLE public.events
ALTER COLUMN event_code SET DEFAULT public.generate_event_code();

ALTER TABLE public.events
ALTER COLUMN share_code SET DEFAULT public.generate_share_code();

Result:
- The app no longer needs to send event_code or share_code during event insert.
- The database owns code generation for all future creation paths.


4. event_code / share_code Column Length Fix
--------------------------------------------

Problem:
- Event insert failed with:
  "value too long for type character varying(10)"
- The generated event code format is "EVT-" plus 8 characters, which is 12
  characters total.
- The live database still had a 10-character limit on at least one code column.

Change:

ALTER TABLE public.events
ALTER COLUMN event_code TYPE character varying;

ALTER TABLE public.events
ALTER COLUMN share_code TYPE character varying;

Result:
- Generated event codes and share codes fit the database columns.
- Event insert succeeded after this fix.


5. Initial RLS Recursion Error
------------------------------

Problem:
- Event insert failed with:
  "infinite recursion detected in policy for relation events"

Cause found in exported policy CSV:
- public.events.events_organiser_all queried public.event_organisers.
- public.events.events_guest_select queried public.event_guests.
- public.event_organisers.event_organisers_manage queried public.events.
- public.event_guests.event_guests_organiser queried public.events and
  public.event_organisers.

Why this breaks:
- A policy on events checked event_organisers.
- The event_organisers policy checked events.
- PostgreSQL re-entered policy evaluation until it detected recursion.


6. RLS Replacement Using SECURITY DEFINER Helpers
-------------------------------------------------

Goal:
- Keep creator, organiser, and guest access.
- Avoid policies directly querying each other.

Policy reset:

DO $$
DECLARE
  policy_record record;
BEGIN
  FOR policy_record IN
    SELECT schemaname, tablename, policyname
    FROM pg_policies
    WHERE schemaname = 'public'
      AND tablename IN (
        'events',
        'event_organisers',
        'event_guests',
        'event_budgets'
      )
  LOOP
    EXECUTE format(
      'DROP POLICY IF EXISTS %I ON %I.%I',
      policy_record.policyname,
      policy_record.schemaname,
      policy_record.tablename
    );
  END LOOP;
END;
$$;

Helper functions:

CREATE OR REPLACE FUNCTION public.is_event_creator(target_event_id uuid)
RETURNS boolean
LANGUAGE sql
SECURITY DEFINER
SET search_path = public
AS $$
  SELECT EXISTS (
    SELECT 1
    FROM public.events
    WHERE id = target_event_id
      AND creator_id = auth.uid()
  );
$$;

CREATE OR REPLACE FUNCTION public.is_event_organiser(target_event_id uuid)
RETURNS boolean
LANGUAGE sql
SECURITY DEFINER
SET search_path = public
AS $$
  SELECT EXISTS (
    SELECT 1
    FROM public.event_organisers
    WHERE event_id = target_event_id
      AND user_id = auth.uid()
      AND status = 'active'
  );
$$;

CREATE OR REPLACE FUNCTION public.is_event_guest(target_event_id uuid)
RETURNS boolean
LANGUAGE sql
SECURITY DEFINER
SET search_path = public
AS $$
  SELECT EXISTS (
    SELECT 1
    FROM public.event_guests
    WHERE event_id = target_event_id
      AND user_id = auth.uid()
  );
$$;

Enable RLS:

ALTER TABLE public.events ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.event_organisers ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.event_guests ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.event_budgets ENABLE ROW LEVEL SECURITY;

Policies:

CREATE POLICY "events_select_related"
ON public.events
FOR SELECT
TO authenticated
USING (
  creator_id = auth.uid()
  OR public.is_event_organiser(id)
  OR public.is_event_guest(id)
);

CREATE POLICY "events_insert_own"
ON public.events
FOR INSERT
TO authenticated
WITH CHECK (creator_id = auth.uid());

CREATE POLICY "events_update_related"
ON public.events
FOR UPDATE
TO authenticated
USING (
  creator_id = auth.uid()
  OR public.is_event_organiser(id)
)
WITH CHECK (
  creator_id = auth.uid()
  OR public.is_event_organiser(id)
);

CREATE POLICY "event_organisers_select_related"
ON public.event_organisers
FOR SELECT
TO authenticated
USING (
  invited_by = auth.uid()
  OR user_id = auth.uid()
  OR public.is_event_creator(event_id)
  OR public.is_event_organiser(event_id)
);

CREATE POLICY "event_organisers_insert_invited_by_self"
ON public.event_organisers
FOR INSERT
TO authenticated
WITH CHECK (
  invited_by = auth.uid()
  AND public.is_event_creator(event_id)
);

CREATE POLICY "event_organisers_update_related"
ON public.event_organisers
FOR UPDATE
TO authenticated
USING (
  user_id = auth.uid()
  OR public.is_event_creator(event_id)
)
WITH CHECK (
  user_id = auth.uid()
  OR public.is_event_creator(event_id)
);

CREATE POLICY "event_guests_select_related"
ON public.event_guests
FOR SELECT
TO authenticated
USING (
  user_id = auth.uid()
  OR public.is_event_creator(event_id)
  OR public.is_event_organiser(event_id)
);

CREATE POLICY "event_guests_insert_manager"
ON public.event_guests
FOR INSERT
TO authenticated
WITH CHECK (
  invited_by = auth.uid()
  AND (
    public.is_event_creator(event_id)
    OR public.is_event_organiser(event_id)
  )
);

CREATE POLICY "event_guests_update_related"
ON public.event_guests
FOR UPDATE
TO authenticated
USING (
  user_id = auth.uid()
  OR public.is_event_creator(event_id)
  OR public.is_event_organiser(event_id)
)
WITH CHECK (
  user_id = auth.uid()
  OR public.is_event_creator(event_id)
  OR public.is_event_organiser(event_id)
);

CREATE POLICY "event_budgets_manage_related"
ON public.event_budgets
FOR ALL
TO authenticated
USING (
  public.is_event_creator(event_id)
  OR public.is_event_organiser(event_id)
)
WITH CHECK (
  public.is_event_creator(event_id)
  OR public.is_event_organiser(event_id)
);

Result:
- Direct policy recursion was removed.
- Authenticated users can insert events where creator_id equals auth.uid().
- Creators can insert organiser rows for their events.
- Event insert from the app started working after the RLS and code-length fixes.


7. App Insert Shape After SQL Changes
-------------------------------------

The Create Event screen now inserts:

{
  creator_id: user.id,
  name: eventName.trim(),
  event_type: isOtherEvent ? customEventType.trim() : eventType.id,
  event_emoji: selectedEventEmoji,
  event_date: formatDateISO(eventDate),
  event_time: formatTimeISO(eventTime),
  venue_name: eventVenue.trim()
}

The app does not send:
- id
- event_code
- share_code
- status
- currency_code
- created_at
- updated_at

Those are handled by database defaults.


8. Fields Left Nullable For Now
-------------------------------

The database includes:
- event_end_date
- event_end_time

The app does not currently collect these fields.

Decision:
- Leave them nullable for now.
- Add optional "Ends" fields later if the event flow needs multi-day or
  scheduled-end support.
