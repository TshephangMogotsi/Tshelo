5. Push Notifications — Built End To End (New Feature)
------------------------------------------------------------------
- Token registration (lib/pushNotifications.ts, new): requests permission
  via expo-notifications, sets the Android notification channel, gets an
  Expo push token (project ID read from
  Constants.expoConfig.extra.eas.projectId), and upserts it into a new
  push_tokens table on conflict expo_push_token.
  registerForPushNotificationsAsync() is called from App.tsx's
  RootNavigator on mount once authenticated + profile complete.
  unregisterPushToken() runs in AuthContext.signOut() before
  supabase.auth.signOut(), deleting the device's token row.
- Notification tap -> deep navigation: App.tsx adds a navigationRef and
  listens via addNotificationResponseReceivedListener +
  getLastNotificationResponseAsync (cold start), routing to FundDetail
  if the payload carries a fundId, else to the new Notifications screen.
- screens/main/NotificationsScreen.tsx (new): lists notifications rows
  (type, title, body, data, is_read), bulk "Read all", tap-to-navigate.
  Icon mapping covers 7 types: join_request, join_approved,
  join_declined, member_joined, member_removed, contribution_added,
  expense_added.
- data/notifications_phase1.sql (server-side triggers, SECURITY DEFINER):
  adds notification.type enum values, a create_notification() helper
  (EXECUTE revoked from client roles), and RLS so clients can only
  select/mark-read their own notifications (cannot insert directly).
  Triggers fire on: fund_members INSERT (join_request to managers, or
  member_joined to managers if already joined), fund_members UPDATE
  (join_approved/join_declined to the requester, member_removed on
  removal), contributions INSERT (contribution_added to all members),
  and expenses INSERT via a statement-level trigger with a transition
  table grouped by fund_id, so one multi-line-item receipt save produces
  one notification per member instead of one per line item.
  BUG FOUND, NOT FIXED: line 211 has a stray "›" character after a
  closing `);` inside notify_fund_member_update() — this is a SQL syntax
  error and the script will fail to run as-is until that character is
  removed.
- data/notifications_phase2.sql: creates the push_tokens table (user_id,
  expo_push_token unique, device_id, platform) with RLS scoped to
  user_id = auth.uid() for all operations — this table is written
  directly by the client, unlike notifications. Notes that the Database
  Webhook (notifications INSERT -> send-push function) has to be wired up
  manually in the Supabase dashboard; it isn't scriptable.
- supabase/functions/send-push/index.ts (new edge function): invoked by
  that webhook, optionally checks a shared secret
  (x-webhook-secret / PUSH_WEBHOOK_SECRET), looks up all push_tokens for
  the notification's user_id, batches the send to Expo's push API
  (exp.host/--/api/v2/push/send), and prunes tokens Expo reports as
  DeviceNotRegistered. README.md documents deploy, secret setup, webhook
  config, and a manual test-insert snippet.
- Wired into navigation (MainNavigator.tsx, types.ts adds
  Notifications: undefined) and into SettingsScreen.tsx / ProfileScreen.tsx,
  whose "Notifications" rows previously had empty onPress handlers.
- No new push-related npm packages were needed — expo-notifications was
  already a dependency. The only new package.json addition today is
  expo-dev-client (~6.0.21), unrelated to push: it's what let eas.json
  gain a development-simulator build profile and switched local dev from
  `expo start --android` to `expo run:android` (this is also the change
  that led into this afternoon's dev-build troubleshooting — see item 10).

10. Native Android Dev Build — Environment Set Up From Scratch
------------------------------------------------------------------
- Diagnosed why `npm run android` (Expo Go path) failed: this project
  uses a custom dev client (com.digitalnatives.tshelo, driven by the new
  expo-dev-client dependency from item 5), which Expo Go can't run —
  push notifications specifically require this, since Expo Go dropped
  remote push support in recent SDKs.
- Switched to `npx expo run:android` to build and install a real dev
  client. Hit and fixed, in order:
    - Stale AVD lock files (hardware-qemu.ini.lock, multiinstance.lock)
      left over from a crashed emulator instance, causing a
      "multiple emulators with same AVD" FATAL error on launch — removed.
    - Missing Java: Gradle couldn't find a JDK. Pointed JAVA_HOME at
      Android Studio's bundled JBR
      (/Applications/Android Studio.app/Contents/jbr/Contents/Home)
      rather than installing a separate JDK.
    - Missing ANDROID_HOME / SDK location: Gradle failed with
      "SDK location not found." Set ANDROID_HOME in .zshrc and wrote
      android/local.properties (sdk.dir) so the build didn't need a new
      shell to pick it up.
    - Build appeared to hang for 9+ minutes on dependency resolution.
      Diagnosed as severe memory pressure, not a real hang: the machine
      has only 8GB RAM, and 6.9GB of 8GB swap was in use with the
      emulator, Gradle daemon, and Android Studio's background JVMs all
      running at once. The emulator process had already crashed under
      the pressure; closing it (or letting it die) freed enough memory
      for Gradle to proceed. Noted as a recurring risk for future native
      builds on this machine — build with the emulator closed, only
      launch it for the final install step.
- Build was left running/in-progress at end of session; not yet
  confirmed installed on-device.
