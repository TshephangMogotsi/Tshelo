2. Home Screen: Removed Mock Data, Loads Live Supabase Data
--------------------------------------------------------------
- HomeScreen previously rendered MOCK_FUNDS / MOCK_SMS hardcoded

3. Join Fund Flow — Built End To End
----------------------------------------
- Added `userId` (string | null) to AuthContext, populated on session
  load, cleared on sign-out, available via useAuth().
- Wired up JoinFundScreen: enter code → look up fund → check fund status
  is active → check not already a member → insert fund_members → navigate
  to FundDetail.
- Fixed a share-code length mismatch: JoinFundScreen required exactly 16
  hex chars, but the DB's generate_fund_share_code() produces 10-char
  alphanumeric codes (e.g. "1972269F69"). Removed the hex-only filter and
  the 4x4 segment display built for 16-char codes; now accepts any
  alphanumeric code ≥6 chars.
- FundCreatedScreen was showing a hardcoded "ABC123" placeholder instead
  of the real share code — now passes and displays the actual code from
  Supabase.
- Discovered and fixed a chicken-and-egg RLS problem: a user couldn't see
  a fund by code because they weren't a member yet. Initially patched with
  a broad "any authenticated user can read all funds" policy, later
  replaced (see #11) with a scoped find_fund_by_code() RPC so general fund
  reads stay restricted to members/owners.
- Added two entry points to JoinFundScreen from HomeScreen: a "Join Fund"
  button in the empty state, and a persistent "Join Fund" pill in the
  "YOUR ITEMS" header.


4. Fund Detail Screen — Hooked To Real Data
------------------------------------------------
- Loads fund + the current user's membership role, then contributions/
  expenses/members, via useFocusEffect + parallel Promise.all calls.
- Replaced a thebeToBWP formatter that was wrong for live data (amounts are
  stored directly in BWP, not thebe) with a correct formatter.
- Added a fund delete feature: a "⋯" menu button in the header, visible to
  the fund owner only (checked via fund.owner_id === userId, not just
  isOrganiser — co-organisers/admins cannot delete). Soft delete via
  deleted_at; HomeScreen's existing `.is('deleted_at', null)` filter makes
  the fund disappear immediately without touching historical
  contribution/expense records.

- Loaded real name/phone/token balance from Supabase into the profile
  card.
- Added an inline "Edit Profile" modal (opened via pencil icon or menu

  including the HomeScreen avatar.
- When name is empty, the edit modal now auto-opens with the title
  "Complete Your Profile" and can't be dismissed without saving — so new

6. Registration / OTP Flow Fixes
-------------------------------------
- Twilio SMS to Botswana (+267) was blocked by default Geo Permissions —
  explained the Twilio Console fix (Messaging → Settings → Geo
  Permissions).
- Diagnosed a test-OTP-number format mismatch: Supabase's test number list
  needs the leading "+" (e.g. +26774271667=123456) to match what the app
  actually sends.
- Fixed OTPScreen's registration path: it used `.update()` on `users`,
  which touches 0 rows (and silently loses the submitted name) if the row
  doesn't exist yet. Initially changed to `.upsert()`, but that hit RLS
  (client can't INSERT into users directly) — reverted to `.update()`.
- Root fix: added a `handle_new_user` Postgres trigger (SECURITY DEFINER)
  that creates the public.users row automatically whenever a new
  auth.users row is created, so the update always has a row to touch. SQL
  was handed to the user and run directly in the Supabase SQL editor.
- Fixed a `bank_account_type` column-doesn't-exist error: the field
  existed in the app's BankDetails TypeScript type but was never added to
  the actual users table. Dropped it from both the OTPScreen upsert and
  ProfileSetupScreen update; kept bank_account_name, which does exist.


7. Fund Creation Bugs (multiple rounds)
--------------------------------------------
- Found and fixed: the "fund only" creation path's Continue button
  navigated straight to FundCreatedScreen without ever calling Supabase —
  no insert happened at all. Added a real handleCreateFund with an
  isCreatingFund loading state.
- Fixed a column mismatch: the app sent `target_date`, but the live schema
  (data/tshelo_db_latest.sql) has `contribution_deadline`. Also started
  saving fund_emoji so the chosen emoji actually persists and shows on
  HomeScreen.
- Fixed a member_status enum bug: CreateFundScreen and JoinFundScreen both
  inserted status: 'active', which isn't a valid value. The actual enum
  (confirmed via `SELECT unnest(enum_range(NULL::member_status))`) is:
  pending, joined, declined, removed, left. Both screens now insert
  status: 'joined'; HomeScreen's exclusion filters were corrected from
  `(left,banned)` / `(left,banned,pending)` to
  `(left,removed,declined)` / `(left,removed,declined,pending)`.
- Fixed a silent-failure chain: the fund_members insert had no error
  handling, so if it failed the app still navigated to FundCreatedScreen
  as if everything succeeded, and the fund would never show up on
  HomeScreen (which only looked up funds via fund_members). Fixed by (a)
  surfacing a real error alert if the fund_members insert fails, and (b)
  making HomeScreen also pull funds by owner_id in addition to
  fund_members, so ownership is never solely dependent on that row
  existing.
- This session's two bugs (already logged in
  fund_creation_sql_edits_log_1.0.txt): 'organiser' isn't a valid
  member_role enum value (only owner/admin/member exist — 'organiser'
  belongs to the separate organiser_role enum used for event
  co-organisers), and the fund_members insert policy required invited_by
  = auth.uid() which the app never set. Also found and fixed that
  self-service joining was structurally impossible under the old policy
  (a joiner is never fund owner/admin) — replaced the live
  fund_members_insert_manager RLS policy to add a self-join branch.


8. share_code vs fund_code Cleanup
----------------------------------------
- Identified that share_code is nullable while fund_code is NOT NULL and
  always generated — using share_code for invites meant a fund could end
  up with no way for anyone to join it.
- Swapped every fund-related use of share_code over to fund_code across
  CreateFundScreen, FundDetailScreen, and JoinFundScreen. Event-related
  code (which has its own separate share_code/event_code pair) was left
  untouched.


9. Home Screen Data Correctness
-------------------------------------
- Fixed role always showing 'organiser': HomeScreen previously hardcoded
  role: 'organiser' on every fund card. Now carries through the user's
  actual role from fund_members (fund_id → role map), and shows a
  "Member" badge on cards where the user isn't the owner/admin.
- Fixed events only checking creator_id: co-organisers added via
  event_organisers (with user_id set once they accept an invite) weren't
  showing the event on their HomeScreen. Now queries event_organisers in
  parallel and combines creator_id = userId OR id IN (co-organiser event
  ids) into a single events query.
- Scoped the whole HomeScreen query set to the current user: funds via
  fund_members (created or joined) plus owner_id fallback, events via
  creator_id or co-organiser membership — previously it had no user
  filter at all and showed every fund/event in the database to every
  user.
- Audited useFocusEffect dependency arrays across HomeScreen,
  ProfileScreen, and FundDetailScreen after a suggestion that some used
  `[]` (stale closures) — confirmed all three already use the correct
  deps ([userId], [userId], [fundId, userId]); no bug found.
